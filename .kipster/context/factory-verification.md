# Factory verification

The factory owns instance startup and teardown. Agents must never run the kit's
start entry themselves, or start/stop an isolated instance through another route.
Use the returned handle's URL, checkout and evidence directory. The kit and its
instructions require human approval; agents never push, open/update a PR or merge.

## Isolation

Never use, inspect, probe or change an owner's installed Kipster, home, database,
ports, app, host job or updater job. Never run root `npm run backend`, `npm run app`,
`scripts/local.sh` or `scripts/local-backend.mjs`. Never borrow provider accounts,
Codex/Claude homes, keys or authentication. No LeafOS operation is part of this kit.

`verify/start.mjs` uses only Core's `openRuntime`, `TextDispatcher`,
`startTextServer` and the compiled deterministic test fixture. It never loads an
execution adapter package or the host loader. It accepts the two allocated ports
and the generated `verify_` database, checks PostgreSQL 18/pgvector and emptiness,
applies migrations through Core, and seeds Factory Owner, Factory Garden and Kip.
IDs are generated by Core; obtain them from bootstrap/directory instead of guessing.
There is no login or password: this is Core's existing trusted-owner boundary,
restricted to loopback for a disposable verification instance.

The instance home lives under `node_modules/.cache/kipster-factory/instance/home`
in the disposable checkout. Runtime environment is constructed from an allowlist,
with isolated HOME and disabled provider homes. Inherited API keys, proxy settings,
NODE_OPTIONS, npm configuration and database overrides are removed before Core
imports. Startup builds Core, the fixture and the production UI itself so tester
preparation works even when the factory omits check. npm must be installed beside
the active Node binary, as with the pinned Node installation.

The UI listens on the first allocated port and streams/proxies HTTP/SSE and media
to Core on the second. The served index sets its saved backend connection to the
UI origin before entry execution, preventing the production client's fixed-port
discovery. `/health` requires a successful real-Core bootstrap. Build mode is
production, never test/demo. Updates are unmanaged, with an empty local catalog;
fetches outside the two allocated origins are refused. No updater is installed.
The browser driver also refuses requests outside the supplied UI origin and uses
an isolated Chrome profile/home. No embedding provider or task-data SQL role is
configured; recording uses a deterministic unavailable transcription provider.

## Deterministic gate

Run root `npm ci`, then `node .kipster/check.mjs`. Read this entry and the delegated
test wrappers before changing it. It runs the local equivalents of CI:

- Require `origin/next`, extract its protocol shape, and run changeset status
  against that ref. A missing trusted ref fails; never substitute HEAD or skip it.
- Root script tests, Core migration gate with `KIPSTER_MIGRATION_BASE=origin/next`,
  script tests, typecheck, package boundaries, protocol shape and base compatibility.
- Core PostgreSQL unit/memory scenario suite and package-consumer tests.
- All four adapters' typechecks and fake CLI/HTTP tests.
- Installer PostgreSQL tests, including launcher tests; on macOS, the CI ad hoc
  backend app build. This writes a new build artifact only, never installed jobs.
- UI lint, format, storage tests, production build and fake-Core conformance/media/
  document tests; compiled deterministic Core fixture; kit isolation/structure
  tests, explicit hidden-file formatting check and JavaScript syntax checks.

The gate uses a fresh disposable HOME and no inherited provider/database variables.
On macOS it honors an explicit DEVELOPER_DIR and resolves SDKROOT through
`xcrun --sdk macosx --show-sdk-path` for that toolchain, without changing global
settings or inheriting an unrelated SDK override.
Core's test wrapper creates a private PostgreSQL 18 Unix-socket-only cluster;
installer's wrapper creates a separate temporary cluster on a randomly allocated
loopback port. Both remove only their own test clusters. PostgreSQL 18 tools and
pgvector must already be installed and on PATH. These are deterministic test
fixtures owned by check, separate from factory-managed app instances.

Native release signing/notarization, Tauri/Rust desktop builds, real provider
readiness/execution, real embeddings/transcription, live login services and actual
update installation are excluded. Existing browser suites use fixed-port test/dev
servers and are not launched by this gate. Independent tester commands in
`verify/README.md` drive the production UI connected to factory-owned real Core.
They do not claim full browser or native-platform coverage.

## Changes

Follow AGENTS.md and decision records. Every changed workspace package needs its
own changeset (patch fix, minor feature/breaking change); kit-only work uses an
empty changeset. Migrations already in `next` are immutable: add the next number
above the base maximum and update Core's ordered runtime list. Responses/events
are additive; follow protocol 5.1.7 for a required protocol bump and old-client
support. Core owns settings and actions, admin catalog/skill parity and tool
contracts; keep provider code in adapters and interface/platform code in the UI.

Record exact commands, exit codes, coverage gaps and commit-linked proof in factory
evidence, never in public READMEs or committed logs/screenshots. Structure and
syntax checks do not prove a boot or user journey. The generated kit remains a
draft until verify-kit runs; independent feature proof remains separate from boot.
